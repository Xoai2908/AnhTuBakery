## 1. Quy Trình Thanh Toán QR Tĩnh Thủ Công (FR-06)

### 1.1 Tổng quan luồng thanh toán

```
[Khách xác nhận đơn hàng]
        │
        ▼
[Hệ thống render trang thanh toán]
   ├── Ảnh QR tĩnh (file ảnh cứng)
   ├── Số tiền cần chuyển (= subtotal + phí ship nếu có)
   └── Nội dung CK tự sinh: "ANHTUBAKERY DH{orderId}"
        │
        ▼
[Khách mở app ngân hàng, quét QR, điền số tiền + nội dung]
        │
        ▼ (ngoài hệ thống — không có callback tự động)
[Tiền về tài khoản gia đình]
        │
        ▼
[Admin mở trang Quản lý → tab "Chờ xác nhận thanh toán"]
[Admin đối chiếu SMS/app ngân hàng với nội dung CK]
[Admin bấm nút "Xác nhận đã thanh toán" cho đúng đơn]
        │
        ▼
[Hệ thống cập nhật: PENDING → PAID → PREPARING]
[SSE tự động thông báo đến khách]
```

#### Quy tắc tính số tiền hiển thị

| Hình thức nhận | Công thức |
|---|---|
| Tự đến lấy | `totalAmount = subtotal` |
| Giao hàng | `totalAmount = subtotal + shippingFee` |

## 2. Thiết Kế Lớp `QrPaymentService` (Tách biệt để dễ nâng cấp)

### 2.1 Mục tiêu thiết kế

Giai đoạn 1 dùng QR tĩnh thủ công. Giai đoạn 2 sẽ tích hợp Webhook tự động (ngân hàng / MoMo gọi callback khi nhận tiền). Để không phải sửa Controller hay Frontend, toàn bộ logic thanh toán được đóng gói trong `QrPaymentService`.

### 2.2 Interface và Implementation

```java
// Interface — Controller chỉ gọi interface này, không biết gì về cơ chế bên trong
public interface QrPaymentService {

    /**
     * Lấy thông tin hiển thị trên trang thanh toán.
     * Trả về: QR image URL, số tiền, nội dung CK, ghi chú.
     */
    PaymentDisplayDto getPaymentDisplay(Long orderId);

    /**
     * Admin xác nhận thanh toán thủ công (Giai đoạn 1).
     * Giai đoạn 2: method này được gọi tự động bởi WebhookController.
     */
    void confirmPayment(Long orderId, String confirmedBy);

    /**
     * Kiểm tra xem đơn đã thanh toán chưa.
     */
    boolean isPaymentConfirmed(Long orderId);
}
```

```java
// Giai đoạn 1 — Admin xác nhận tay
@Service
@Primary
public class ManualQrPaymentService implements QrPaymentService {

    private final OrderRepository orderRepository;
    private final OrderStatusService orderStatusService;

    @Value("${payment.qr-image-url}")          // cấu hình trong application.yml
    private String qrImageUrl;

    @Override
    public PaymentDisplayDto getPaymentDisplay(Long orderId) {
        Order order = orderRepository.findById(orderId).orElseThrow();
        return PaymentDisplayDto.builder()
            .qrImageUrl(qrImageUrl)
            .amount(order.getTotalAmount())          // subtotal + shippingFee
            .paymentReference(order.getPaymentReference())
            .note("Sau khi chuyển khoản, vui lòng chờ Anh Tu Bakery xác nhận.")
            .build();
    }

    @Override
    public void confirmPayment(Long orderId, String confirmedBy) {
        // Chuyển trạng thái PENDING → PAID → PREPARING
        orderStatusService.transitionTo(orderId, OrderStatus.PAID, confirmedBy);
        orderStatusService.transitionTo(orderId, OrderStatus.PREPARING, confirmedBy);
    }
}
```

## 3. Cơ Chế Server-Sent Events (FR-07)

### 3.1 Tổng quan SSE

Server-Sent Events (SSE) cho phép server chủ động đẩy dữ liệu đến trình duyệt qua một kết nối HTTP mở. Không cần WebSocket, không cần thư viện ngoài — Spring Boot hỗ trợ sẵn.

```
Client (Browser)                    Server (Spring Boot)
      │                                      │
      │── GET /api/orders/123/stream ────────►│
      │◄─────────────── 200 OK ──────────────│
      │◄─── text/event-stream ───────────────│
      │     (kết nối giữ mở)                 │
      │                                      │
      │ ... Admin bấm "Đã chuẩn bị xong" ... │
      │                                      │
      │◄─── event: ORDER_READY ──────────────│
      │     data: {"orderId":123,...}        │
      │                                      │
      │ ... Kết nối đóng hoặc client tự đóng │
```

### 3.2 Endpoint SSE

```java
@RestController
@RequestMapping("/api/orders")
public class OrderStreamController {

    private final SseEmitterRegistry emitterRegistry;
    private final OrderRepository orderRepository;

    /**
     * Khách hàng kết nối vào đây ngay sau khi đặt đơn thành công.
     * orderId: mã đơn hàng
     * phone:   số điện thoại để xác minh quyền truy cập
     */
    @GetMapping("/{orderId}/stream")
    public SseEmitter streamOrderStatus(
            @PathVariable Long orderId,
            @RequestParam String phone) {

        // Xác minh SĐT khớp với đơn hàng (bảo mật tối thiểu)
        Order order = orderRepository.findById(orderId).orElseThrow();
        if (!order.getCustomerPhone().equals(phone)) {
            throw new AccessDeniedException("Số điện thoại không khớp.");
        }

        // Timeout 30 phút — đủ cho một đơn bánh mì thông thường
        SseEmitter emitter = new SseEmitter(30 * 60 * 1000L);
        emitterRegistry.register(orderId, emitter);

        // Gửi trạng thái hiện tại ngay lập tức (khách vừa kết nối)
        sendCurrentStatus(emitter, order);

        emitter.onCompletion(() -> emitterRegistry.remove(orderId));
        emitter.onTimeout(() -> emitterRegistry.remove(orderId));

        return emitter;
    }
}
```

### 3.3 Registry quản lý Emitter

```java
@Component
public class SseEmitterRegistry {

    // Một đơn có thể có nhiều tab đang xem (ví dụ: khách mở 2 tab)
    private final Map<Long, List<SseEmitter>> emitters = new ConcurrentHashMap<>();

    public void register(Long orderId, SseEmitter emitter) {
        emitters.computeIfAbsent(orderId, k -> new CopyOnWriteArrayList<>()).add(emitter);
    }

    public void remove(Long orderId, SseEmitter emitter) {
        List<SseEmitter> list = emitters.get(orderId);
        if (list != null) list.remove(emitter);
    }

    public void remove(Long orderId) {
        emitters.remove(orderId);
    }

    public List<SseEmitter> getEmitters(Long orderId) {
        return emitters.getOrDefault(orderId, Collections.emptyList());
    }
}
```

### 3.4 Service gửi sự kiện khi Admin đổi trạng thái

```java
@Service
public class OrderNotificationService {

    private final SseEmitterRegistry emitterRegistry;

    /**
     * Gọi sau khi Admin chuyển đơn sang trạng thái READY.
     * Nội dung thông báo khác nhau tùy hình thức nhận hàng.
     */
    public void notifyOrderReady(Order order) {
        String message = buildReadyMessage(order);
        sendToOrder(order.getId(), "ORDER_READY", message);
    }

    public void notifyOrderConfirmed(Order order) {
        String message = "✅ Đơn #" + order.getId() + " đã xác nhận. Đang chuẩn bị...";
        sendToOrder(order.getId(), "ORDER_CONFIRMED", message);
    }

    public void notifyPaymentConfirmed(Order order) {
        String message = "💰 Thanh toán đơn #" + order.getId() + " đã xác nhận.";
        sendToOrder(order.getId(), "PAYMENT_CONFIRMED", message);
    }

    // --- Private helpers ---

    private String buildReadyMessage(Order order) {
        String orderId = "#" + order.getId();
        return switch (order.getDeliveryType()) {
            case PICKUP   -> "🎉 Đơn " + orderId + " xong rồi! Mời đến lấy tại quán.";
            case DELIVERY -> "🚀 Đơn " + orderId + " xong rồi! Shipper sẽ sớm đến bạn.";
        };
    }

    private void sendToOrder(Long orderId, String eventType, String message) {
        List<SseEmitter> list = emitterRegistry.getEmitters(orderId);
        List<SseEmitter> stale = new ArrayList<>();

        for (SseEmitter emitter : list) {
            try {
                emitter.send(SseEmitter.event()
                    .name(eventType)
                    .data(Map.of(
                        "orderId", orderId,
                        "message", message,
                        "timestamp", Instant.now().toString()
                    )));
            } catch (IOException e) {
                stale.add(emitter);   // Emitter đã chết — đánh dấu xoá
            }
        }
        stale.forEach(e -> emitterRegistry.remove(orderId, e));
    }
}
```

### 3.5 Bảng ánh xạ sự kiện đầy đủ

| Sự kiện hệ thống | Event Name (SSE) | Tự đến lấy | Giao hàng |
|---|---|---|---|
| Admin xác nhận đơn | `ORDER_CONFIRMED` | ✅ "Đơn #X đã xác nhận. Đang chuẩn bị..." | ✅ (giống nhau) |
| Admin duyệt thanh toán | `PAYMENT_CONFIRMED` | 💰 "Thanh toán đơn #X đã xác nhận." | 💰 (giống nhau) |
| Admin bấm "Đã chuẩn bị xong" | `ORDER_READY` | 🎉 "...Mời đến lấy tại quán." | 🚀 "...Shipper sẽ sớm đến bạn." |
| Admin đổi sang DELIVERING | `ORDER_DELIVERING` | *(không áp dụng)* | 🛵 "Shipper đang trên đường đến bạn." |
| Admin đóng đơn COMPLETED | `ORDER_COMPLETED` | 🏁 "Đơn #X đã hoàn thành. Cảm ơn!" | 🏁 (giống nhau) |

### 3.6 Xử lý phía Frontend (JavaScript)

```javascript
// Kết nối SSE ngay sau khi đặt đơn thành công
function connectOrderStream(orderId, phone) {
    const url = `/api/orders/${orderId}/stream?phone=${encodeURIComponent(phone)}`;
    const evtSource = new EventSource(url);

    // Xử lý từng loại sự kiện
    evtSource.addEventListener('ORDER_CONFIRMED',   e => showToast(JSON.parse(e.data).message));
    evtSource.addEventListener('PAYMENT_CONFIRMED', e => showToast(JSON.parse(e.data).message));
    evtSource.addEventListener('ORDER_READY',       e => {
        showToast(JSON.parse(e.data).message, { duration: 0 }); // không tự đóng
        evtSource.close(); // Đơn xong, không cần giữ kết nối
    });

    // Tự động kết nối lại sau 5 giây nếu bị đứt
    evtSource.onerror = () => {
        evtSource.close();
        setTimeout(() => connectOrderStream(orderId, phone), 5000);
    };
}
```

### 3.7 Xử lý thông báo tồn đọng (Khách đóng tab)

Khi khách đóng tab sau khi đặt đơn, SSE mất kết nối. Hệ thống lưu lịch sử sự kiện trong DB để hiển thị lại khi khách quay lại.

```java
// Bảng order_events — lưu toàn bộ sự kiện của đơn

    private Long orderId;
    private String eventType;    // ORDER_CONFIRMED, ORDER_READY, ...

    private boolean sentViaSse;  // Đã gửi SSE thành công chưa?
```

## 4. Lộ Trình Nâng Cấp Giai Đoạn 2

| Hạng mục | Giai đoạn 1 (hiện tại) | Giai đoạn 2 (nâng cấp) |
|---|---|---|
| Xác nhận thanh toán | Admin bấm thủ công | Webhook tự động từ ngân hàng/MoMo |
| Thông báo push | SSE (chỉ khi tab đang mở) | Web Push VAPID (cả khi đóng tab) |

| Chi phí | 0 VNĐ | SMS API: ~500đ/tin; VAPID: miễn phí |
