## 1. Quy trình phê duyệt Đại lý (FR-01)

### 1.1 API đăng ký Đại lý

**Endpoint:** `POST /wholesale/register`  
**Auth:** Không yêu cầu đăng nhập  
**Content-Type:** `application/x-www-form-urlencoded` hoặc `application/json`

**Request body:**

| Tham số | Kiểu | Ràng buộc | Mô tả |
|---------|------|-----------|-------|
| `fullName` | String | NotBlank, max 100 | Họ tên đại diện |
| `phone` | String | Pattern `^\d{10}$`, Unique | Số điện thoại 10 chữ số |
| `shopName` | String | NotBlank, max 150 | Tên cửa hàng / đại lý |
| `deliveryAddress` | String | NotBlank | Địa chỉ giao hàng đầy đủ |
| `latitude` | Double | Range [-90, 90] | Vĩ độ |
| `longitude` | Double | Range [-180, 180] | Kinh độ |
| `password` | String | MinLength 6 | Mật khẩu |
| `confirmPassword` | String | Matches `password` | Xác nhận mật khẩu |

**Response thành công (201 Created):**
```json
{
  "status": "success",
  "message": "Đăng ký thành công. Vui lòng chờ Admin xét duyệt.",
  "agentId": 42
}
```

**Response lỗi validation (400 Bad Request):**
```json
{
  "status": "error",
  "errors": {
    "phone": "Số điện thoại này đã có tài khoản. Vui lòng đăng nhập.",
    "password": "Mật khẩu tối thiểu 6 ký tự."
  }
}
```

### 1.2 Luồng xử lý Backend sau khi nhận form

```
1. Validate đầu vào (Bean Validation)
2. Kiểm tra phone đã tồn tại trong bảng users → lỗi 400 nếu trùng
3. Hash password bằng BCrypt (strength = 12)
4. Tạo bản ghi users (role = AGENT)
5. Tạo bản ghi agents (status = PENDING)
6. Ghi log ra console (môi trường demo):
   "[THÔNG BÁO] Đại lý mới: {fullName} - {phone} đang chờ duyệt.
    Vào Admin > Đại lý để xét duyệt."
7. Trả về 201 Created
```

> **Môi trường thực tế (giai đoạn 2):** Thay bước 6 bằng gọi ESMS API gửi SMS đến `${bakery.admin.phone}`.

### 1.3 API Admin kích hoạt / tạm khóa Đại lý

**Kích hoạt:**  
`PATCH /admin/agents/{id}/activate`  
- Điều kiện: agent.status == PENDING  
- Hành động: Chuyển status → ACTIVE, ghi `activated_at = now()`

**Tạm khóa:**  
`PATCH /admin/agents/{id}/suspend`  
- Điều kiện: agent.status == ACTIVE  
- Hành động: Chuyển status → SUSPENDED

**Mở khóa:**  
`PATCH /admin/agents/{id}/reactivate`  
- Điều kiện: agent.status == SUSPENDED  
- Hành động: Chuyển status → ACTIVE

### 1.4 Màn hình Admin — Danh sách Đại lý chờ duyệt

| Cột hiển thị | Nguồn dữ liệu |
|-------------|--------------|
| Tên đại diện | `users.full_name` |
| Số điện thoại | `users.phone` |
| Tên cửa hàng | `agents.shop_name` |
| Địa chỉ | `agents.delivery_address` |
| Khoảng cách | Tính real-time bằng Haversine (km) |
| Thời gian đăng ký | `users.created_at` |
| Trạng thái | Badge màu: 🟡 PENDING / 🟢 ACTIVE / 🔴 SUSPENDED |
| Hành động | Nút Kích hoạt / Tạm khóa / Mở khóa |

## 2. Thuật toán Giá sỉ bậc thang (FR-02)

### 2.1 Quy tắc nghiệp vụ

| Số lượng (ổ/đơn) | Đơn giá | Hành vi hệ thống |
|------------------|---------|-----------------|
| < 50 | — | Trả lỗi HTTP 400, không tạo đơn |
| 50 – 199 | **1.500 VNĐ/ổ** | Tính bình thường |
| ≥ 200 | **1.300 VNĐ/ổ** | Tính bình thường |

### 2.2 Cài đặt logic Backend

```java
@Service
public class WholesalePricingServiceImpl implements WholesalePricingService {

    @Value("${bakery.wholesale.min-quantity}")
    private int minQuantity; // 50

    @Value("${bakery.wholesale.tier1-max-quantity}")
    private int tier1Max; // 199

    @Value("${bakery.wholesale.tier1-price}")
    private int tier1Price; // 1500

    @Value("${bakery.wholesale.tier2-price}")
    private int tier2Price; // 1300

    @Override
    public WholesalePriceResult calculate(int quantity) {
        if (quantity < minQuantity) {
            throw new IllegalArgumentException(
                "Đặt sỉ tối thiểu " + minQuantity + " ổ. " +
                "Vui lòng liên hệ để mua lẻ."
            );
        }

        int unitPrice = (quantity <= tier1Max) ? tier1Price : tier2Price;
        int totalAmount = unitPrice * quantity;
        String tier = (quantity <= tier1Max) ? "TIER_1" : "TIER_2";

        return new WholesalePriceResult(unitPrice, totalAmount, tier);
    }
}
```

### 2.3 API tính giá real-time (dùng cho UI)

**Endpoint:** `GET /api/wholesale/pricing?quantity={n}`  
**Auth:** Chỉ AGENT đã ACTIVE  

**Response (200 OK):**
```json
{
  "quantity": 180,
  "unitPrice": 1500,
  "totalAmount": 270000,
  "tier": "TIER_1",
  "hint": "Đặt thêm 20 ổ để được giá 1.300đ/ổ (tiết kiệm 36.000đ).",
  "shippingFee": 0
}
```

**Trường `hint` — logic tính:**
- Nếu đang ở TIER_1 và `200 - quantity <= 50`: hiển thị gợi ý lên TIER_2.
- Nếu đã ở TIER_2 hoặc hint không đáng kể: `hint = null`.

### 2.4 Yêu cầu UI — Hiển thị real-time

Khi đại lý nhập/thay đổi số lượng trong form đặt đơn sỉ:

```
┌──────────────────────────────────────────────────────┐
│  Số lượng mì ổ:  [    180    ]                        │
│                                                      │
│  Đơn giá hiện tại:    1.500 đ/ổ                      │
│  Thành tiền dự kiến:  270.000 đ                      │
│  Phí giao hàng:       Miễn phí ✓                    │
│                                                      │
│  💡 Đặt thêm 20 ổ để được giá 1.300đ/ổ              │
│     (tiết kiệm 36.000đ so với đơn hiện tại)          │
└──────────────────────────────────────────────────────┘
```

- Debounce gọi API: 300ms sau khi ngừng gõ.
- Hiển thị spinner nhỏ khi đang tính.
- Tô đỏ ô nhập + hiện thông báo lỗi nếu quantity < 50.

## 3. Kiểm tra phạm vi & Phí giao hàng sỉ (FR-03)

### 3.1 Công thức Haversine — Cài đặt

```java
@Component
public class HaversineDistanceCalculator implements DistanceCalculator {

    private static final double EARTH_RADIUS_KM = 6371.0;

    @Override
    public double calculate(double lat1, double lon1, double lat2, double lon2) {
        double dLat = Math.toRadians(lat2 - lat1);
        double dLon = Math.toRadians(lon2 - lon1);

        double a = Math.sin(dLat / 2) * Math.sin(dLat / 2)
                 + Math.cos(Math.toRadians(lat1))
                 * Math.cos(Math.toRadians(lat2))
                 * Math.sin(dLon / 2) * Math.sin(dLon / 2);

        double c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
        return EARTH_RADIUS_KM * c;
    }
}
```

### 3.2 Kiểm tra phạm vi khi Đại lý đặt đơn

```java
// Trong WholesaleOrderService.createOrder()
double distanceKm = distanceCalculator.calculate(
    bakeryLat, bakeryLon,
    agent.getLatitude(), agent.getLongitude()
);

if (distanceKm > maxRadiusKm) { // maxRadiusKm = 5.0
    throw new OutOfServiceAreaException(
        String.format(
            "Rất tiếc, địa chỉ của bạn nằm ngoài vùng phục vụ " +
            "(%.1f km, tối đa %.0f km).",
            distanceKm, maxRadiusKm
        )
    );
}
```

### 3.3 Cách lấy tọa độ đại lý

| Phương án | Mô tả | Môi trường |
|-----------|-------|-----------|
| **Phương án A** | Đại lý nhập thủ công latitude/longitude vào form | Demo |
| **Phương án B** | Nút "Lấy vị trí hiện tại" dùng `navigator.geolocation.getCurrentPosition()` | Thực tế |

**Snippet JS — Phương án B:**
```javascript
document.getElementById('btn-get-location').addEventListener('click', () => {
    if (!navigator.geolocation) {
        alert('Trình duyệt không hỗ trợ định vị.');
        return;
    }
    navigator.geolocation.getCurrentPosition(
        (pos) => {
            document.getElementById('latitude').value = pos.coords.latitude.toFixed(7);
            document.getElementById('longitude').value = pos.coords.longitude.toFixed(7);
            // Gọi API kiểm tra phạm vi ngay
            checkDeliveryRadius(pos.coords.latitude, pos.coords.longitude);
        },
        (err) => alert('Không lấy được vị trí: ' + err.message)
    );
});
```

### 3.4 API kiểm tra phạm vi real-time

**Endpoint:** `GET /api/wholesale/check-radius?lat={lat}&lon={lon}`  
**Auth:** Không yêu cầu (dùng lúc đăng ký)

**Response (trong phạm vi):**
```json
{
  "withinRange": true,
  "distanceKm": 3.24,
  "shippingFee": 0,
  "message": "Địa chỉ của bạn trong vùng phục vụ (3.2 km). Miễn phí giao hàng."
}
```

**Response (ngoài phạm vi):**
```json
{
  "withinRange": false,
  "distanceKm": 6.85,
  "shippingFee": null,
  "message": "Rất tiếc, địa chỉ của bạn nằm ngoài vùng phục vụ (6.9 km, tối đa 5 km)."
}
```

### 3.5 Phí giao hàng sỉ

- **Cố định: 0 VNĐ** cho mọi đơn sỉ trong phạm vi 5km.
- Lưu `orders.shipping_fee = 0` vào DB.
- Hiển thị "Miễn phí giao hàng ✓" trên màn hình xác nhận đơn.

## 4. Luồng đặt đơn sỉ đầy đủ

```
[Đại lý đăng nhập (ACTIVE)]
       ↓
[Nhập số lượng mì ổ]
       ↓ (real-time: tính giá + gợi ý)
[Xác nhận đơn hàng]
       ↓
[Backend kiểm tra: quantity ≥ 50 + địa chỉ ≤ 5km]
       ↓ (pass)
[Tạo đơn: status = PENDING, shipping_fee = 0]
       ↓
[Hiển thị màn hình QR thanh toán]
       ↓
[Admin xác nhận → PAID → PREPARING → READY → COMPLETED]
```

## 5. Xử lý lỗi & Edge Cases — Phân hệ Sỉ

| Tình huống | HTTP Code | Thông báo hiển thị |
|------------|-----------|-------------------|
| Số lượng < 50 | 400 | "Đặt sỉ tối thiểu 50 ổ. Vui lòng liên hệ để mua lẻ." |
| Địa chỉ ngoài 5km | 422 | "Rất tiếc, địa chỉ nằm ngoài vùng phục vụ (X.X km, tối đa 5 km)." |
| SĐT đã đăng ký | 409 | "Số điện thoại này đã có tài khoản. Vui lòng đăng nhập." |
| Đại lý PENDING đặt đơn | 403 | "Tài khoản đang chờ duyệt. Vui lòng chờ xác nhận từ Anh Tu Bakery." |
| Đại lý SUSPENDED đặt đơn | 403 | "Tài khoản đã bị tạm khóa. Vui lòng liên hệ hỗ trợ." |
| Tọa độ không hợp lệ | 400 | "Tọa độ không hợp lệ. Vui lòng nhập lại." |
